# 工作流 V2 第二阶段实施清单

> 日期：2026-03-31
> 目标：在不改主链拓扑的前提下，把单层 `retrieval_context` 升级为三层 `retrieval_bundle`，并让现有 `planning -> assembly -> coding` 链路继续可用。

## 范围

- 包含：三层检索结果包、AHU 模板/骨架索引、兼容层、Planner 轻改、回归测试。
- 不包含：`ArchitecturePlanner / SubsystemPlanner / GlobalAssembler`、`RepairRouter / RepairAgent`、人工澄清节点。

## 实施顺序

### 1. 先立契约和兼容层

- 修改文件：
  - `workflow.py`
  - `workflow_trace.py`
  - 建议新增 `utils/retrieval_bundle_utils.py`
- 改动：
  - `WorkflowState` 增加 `retrieval_bundle`
  - 初始化 state 增加 `retrieval_bundle = {}`
  - 提供 3 个兼容 helper：
    - `build_legacy_retrieval_context(bundle)`
    - `get_atomic_modules(bundle_or_context)`
    - `build_compilable_doc_map(bundle_or_context)`
  - 规则：Phase 2 期间继续保留 `retrieval_context`，其语义等价于 `retrieval_bundle.atomic_modules` 的旧视图
- 补充测试：
  - 新增 `tests/test_phase2_retrieval_bundle.py`
  - 覆盖 state 初始化、bundle -> legacy 映射、旧 consumer 在只有 `retrieval_context` 时仍可工作

### 2. 建立 AHU 三层知识资产

- 修改文件：
  - `config.py`
  - 建议新增 `scripts/build_phase2_retrieval_indexes.py`
  - 建议新增 `utils/ahu_knowledge_builder.py`
  - 建议新增 `AHU程序/pattern_library/` 用于落盘归一化结果
- 改动：
  - 新增 3 个 collection 配置：
    - `atomic_modules`
    - `subflow_templates`
    - `system_patterns`
  - 从 `schemas/` 构建原子模块索引
  - 从 `AHU程序/flows_*.json` 提取并归一化子流程模板
  - 从同一批 flow 提取系统骨架模式：页签、子流程组合、命名/布局提示、可选页签
- 结构设计补充：
  - 总体原则：
    - 继续沿用 `docs/knowledge_base_architecture.md` 的知识库存储思路：`document` 负责 embedding 检索，`metadata` 负责过滤与索引，完整结构化对象以字符串形式放入 `payload_json`
    - `atomic_modules` 直接继承现有模块知识库设计，不重造一套新 schema；Phase 2 只是把它显式纳入三层 `retrieval_bundle`
    - `subflow_templates` 和 `atomic_modules` 都属于“可编译文档”，后续都要能进入 `build_compilable_doc_map(bundle)` 的结果
    - `system_patterns` 属于“架构先验”，服务 Planning，不直接进入 Assembly / Compiler 的 `doc_map`
    - `style_guides` 阶段性不单独建 collection，优先作为 `system_patterns` 的派生视图返回
  - 建议统一 collection 记录外壳：
    ```json
    {
      "id": "stable_id",
      "document": "用于语义检索的文本",
      "metadata": {
        "asset_type": "atomic_module | subflow_template | system_pattern",
        "title": "名称",
        "category_l1": "",
        "category_l2": "",
        "system_type": "AHU",
        "keywords": "逗号拼接后的关键词",
        "source_file": "",
        "version": "v1",
        "payload_json": "{...完整结构化对象...}"
      }
    }
    ```
  - `atomic_modules` 结构：
    - 数据来源：现有 `schemas/*.json`
    - 与当前 `kong_modules_v1` 保持同一设计哲学，可视为现有库的显式命名或兼容扩展
    - `payload_json` 建议继续保存当前模块 schema 原样结构：
    ```json
    {
      "module_type": "compare",
      "name": "比较判断",
      "category": "逻辑模块/比较判断",
      "description": "",
      "keywords": [],
      "usage_guides": [],
      "parameters_schema": {},
      "ports_definition": {},
      "template_json": {}
    }
    ```
    - Retrieval 运行时返回给 `retrieval_bundle.atomic_modules[*]` 的对象继续对齐当前 `retrieval_context.relevant_nodes[*]`，便于兼容旧 consumer
  - `subflow_templates` 结构：
    - 数据来源：`AHU程序/flows_*.json` 中的 `type = subflow` 定义及其内部子图对象
    - 不能只存 subflow 头对象；至少要同时保存“接口定义 + 内部 raw objects + 编译摘要”
    - `payload_json` 建议结构：
    ```json
    {
      "template_id": "ahu_supply_fan_std__9in4out__v1",
      "template_name": "末端组空送风机标准控制",
      "template_role": "supply_fan_control",
      "system_type": "AHU",
      "description": "送风机启停、故障、可用性标准控制模板",
      "keywords": [],
      "usage_guides": [],
      "ports_definition": {
        "inputs": [],
        "outputs": []
      },
      "parameters_schema": {},
      "template_json": {
        "type": "subflow",
        "name": "末端组空送风机标准控制",
        "in": [],
        "out": [],
        "inputs": 9,
        "outputs": 4
      },
      "internal_flow_objects": [],
      "dependency_module_types": ["quote", "swInput", "logic", "switch", "delayOn"],
      "compile_hints": {
        "supports_multi_instance": true
      },
      "source_info": {
        "source_flows": [],
        "signature_hash": ""
      }
    }
    ```
    - `template_id` 不直接使用 flow 内随机 `id`，而是使用“归一化名称 + IO 签名 + 内部拓扑签名”生成稳定主键
    - 归一化时应排除项目名、站点名、随机节点 ID、实例坐标漂移等与模板身份无关的信息
  - `system_patterns` 结构：
    - 数据来源：同一批 `AHU程序/flows_*.json`，但抽取对象是系统骨架而非可编译模板
    - 重点承载：页签骨架、子系统槽位、模板候选、命名/布局提示、可选页签
    - `payload_json` 建议结构：
    ```json
    {
      "pattern_id": "ahu_ctrl_chw_heater_co2__v1",
      "pattern_name": "AHU 控制骨架",
      "system_type": "AHU",
      "description": "适用于送风机、冷水阀、电加热、CO2 联动的 AHU 系统骨架",
      "feature_tags": ["supply_fan", "chw_valve", "electric_heater", "co2"],
      "required_pages": [
        {"page_key": "io_comm", "label": "IO/通讯", "kind": "io"},
        {"page_key": "control", "label": "控制", "kind": "control"}
      ],
      "optional_pages": [
        {"page_key": "timing", "label": "定时", "kind": "timing"},
        {"page_key": "dx_status", "label": "直膨机状态", "kind": "status"}
      ],
      "subsystem_slots": [
        {
          "slot_id": "supply_fan_ctrl_1",
          "slot_role": "supply_fan_control",
          "page_key": "control",
          "binding_mode": "prefer_subflow",
          "candidate_template_ids": ["ahu_supply_fan_std__9in4out__v1"]
        }
      ],
      "naming_hints": {},
      "layout_hints": {},
      "style_guides": {},
      "source_cases": []
    }
    ```
    - `system_patterns` 不要求强行具备 `template_json` / `ports_definition` 的模块式结构；它是架构约束对象，不是编译模板对象
    - 页签标签需要做归一化，避免把 `IO/通讯(安宁中医院）` 这类项目名直接写入模式主键；应保留稳定页签键，如 `io_comm / control / timing / dx_status`
  - 与 `retrieval_bundle` 的映射关系：
    ```json
    {
      "atomic_modules": [],
      "subflow_templates": [],
      "system_patterns": [],
      "style_guides": [],
      "metadata": {
        "selected_case_pattern_id": "",
        "retrieved_atomic_count": 0,
        "retrieved_subflow_count": 0,
        "retrieved_pattern_count": 0
      }
    }
    ```
    - `build_legacy_retrieval_context(bundle)` 只需要把 `atomic_modules` 退化映射为旧 `relevant_nodes`
    - `build_compilable_doc_map(bundle)` 只聚合 `atomic_modules + subflow_templates`
    - `system_patterns` 只参与 Planning 阶段的架构提示，不直接下沉到 Compiler
- 补充测试：
  - 新增 `tests/test_phase2_ahu_knowledge_builder.py`
  - 覆盖：
    - 子流程模板 ID 稳定
    - 项目名和随机节点 ID 不进入模板主键
    - 系统骨架能正确提取 `控制 / 定时 / 直膨机状态` 等稳定页签
