# 工作流后端启动与联调说明

> 最后更新：2026-04-23
> 适用范围：`app/` FastAPI 服务层与 `workflow_trace.py` 正式工作流入口。

## 1. 本地启动

先确认已安装依赖：

```powershell
conda activate midea
python -m pip install -r requirements.txt
```

启动 API 服务：

```powershell
conda activate midea
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

默认配置：

- `WORKFLOW_CHECKPOINTER_BACKEND=sqlite`
- `WORKFLOW_CHECKPOINT_DB_PATH=outputs/workflow_api/checkpoints.sqlite3`
- `WORKFLOW_RUN_REPOSITORY_PATH=outputs/workflow_api/runs.json`

`memory` checkpointer 只用于单测或临时 demo，不作为前后端联调默认配置。

## 2. 运行契约

- `thread_id` 是 LangGraph checkpoint 恢复指针。
- `attempt_id` 是 API、trace、前端展示层的一次运行主键。
- 同一 `thread_id` 同一时刻只允许一个 active attempt。
- active attempt 状态包括 `queued`、`running`、`interrupted`。
- `completed`、`rejected`、`failed` 是终态，不允许再次 `resume`。
- `POST /resume` 必须匹配当前 active interrupted attempt 的 `attempt_id` 和 `review_id`。

V1 对外状态机：

```text
queued -> running
running -> interrupted
running -> completed
running -> rejected
running -> failed
interrupted -> running
```

## 3. 核心接口

创建运行：

```powershell
Invoke-RestMethod `
  -Method Post `
  -Uri "http://127.0.0.1:8000/api/workflow/runs" `
  -ContentType "application/json" `
  -Body '{
    "user_query": "为 AHU 生成送风机与电加热联动控制",
    "title": "AHU 控制方案",
    "enable_hitl_clarification": true,
    "enable_hitl_architecture_review": true,
    "runtime_metadata": {"source": "frontend"}
  }'
```

轮询 attempt：

```powershell
Invoke-RestMethod `
  -Method Get `
  -Uri "http://127.0.0.1:8000/api/workflow/threads/<thread_id>/attempts/<attempt_id>"
```

提交 review：

```powershell
Invoke-RestMethod `
  -Method Post `
  -Uri "http://127.0.0.1:8000/api/workflow/threads/<thread_id>/resume" `
  -ContentType "application/json" `
  -Body '{
    "attempt_id": "<attempt_id>",
    "review_id": "<review_id>",
    "decision": "approve",
    "answers": [],
    "feedback": "",
    "updated_constraints": {}
  }'
```

查询结果：

```powershell
Invoke-RestMethod `
  -Method Get `
  -Uri "http://127.0.0.1:8000/api/workflow/threads/<thread_id>/attempts/<attempt_id>/result"
```

查询 trace 摘要：

```powershell
Invoke-RestMethod `
  -Method Get `
  -Uri "http://127.0.0.1:8000/api/workflow/threads/<thread_id>/attempts/<attempt_id>/trace"
```

查询调试状态历史：

```powershell
Invoke-RestMethod `
  -Method Get `
  -Uri "http://127.0.0.1:8000/api/workflow/threads/<thread_id>/attempts/<attempt_id>/state-history?limit=10"
```

健康检查：

```powershell
Invoke-RestMethod `
  -Method Get `
  -Uri "http://127.0.0.1:8000/api/workflow/health"
```

## 4. 前端稳定字段

前端可以依赖：

- `thread_id`
- `attempt_id`
- `status`
- `current_step`
- `review.review_id`
- `review.stage`
- `review.status`
- `review.question`
- `review.options`
- `review.context_summary`
- `result.json_text`
- `result.compile_report`
- `result.verification_report`
- `trace.summary`

前端暂时不要强依赖：

- 完整 `WorkflowState`
- 完整节点 IO trace
- trace 文件物理路径
- 固定串行节点数量
- 百分比进度
- 任意内部规划对象

`subtasks` 已在 attempt detail 中预留，当前默认返回空数组，后续用于 `Send/reducer` 子任务展示。

## 5. 错误结构

所有 API 错误统一为：

```json
{
  "error": {
    "code": "conflict",
    "message": "当前 thread 已存在 active attempt，请等待完成或恢复当前 review。",
    "details": {}
  }
}
```

当前稳定错误码：

- `not_found`
- `conflict`
- `validation_error`
- `dependency_unavailable`
- `internal_error`
