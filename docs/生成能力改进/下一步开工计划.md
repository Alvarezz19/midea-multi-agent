# 复杂 AHU 生成能力下一步开工计划

> 编写日期：2026-04-24  
> 适用范围：承接《复杂 AHU 流程 JSON 生成能力改进方案》，作为下一轮可直接开工的工作清单。  
> 当前策略：默认不启用 `RepairAgent`，保留 `repair_router`；先做轻量知识资产分层，把 `schemas/*.json` 升级为可消费合同，再补平台 JSON 合同和子流程 body 编译，最后引入 LLM 质量增强。  
> 执行记录：第一轮已完成知识合同加载器、平台 flow schema 最小校验、`internal_flow_objects` 入 Graph IR、CodingAgent body 展开、strict compile 诊断、Verifier body 校验、trace 编译诊断字段和最小 workflow 闭环测试。

---

## 1. 开工目标

下一轮只做一个最小但完整的质量闭环：

```text
真实子流程模板
-> 知识资产 registry / contract loader 可定位模板和原子模块合同
-> Graph IR 携带 body
-> CodingAgent 展开 body
-> 基于 `schemas` 和 flow schema 的 verifier 验收
-> trace / compile_report 能解释结果
```

第一轮目标不追完整 AHU 900+ 对象程序，只要求以“末端组空送风机标准控制”模板为代表，生成带完整 subflow body 的平台 JSON。

第一轮也不做大规模知识库补全。知识相关工作只做轻量前置：明确事实源、缓存、索引和按需加载口径，确保后续阶段补充的知识能被工作流稳定检索和消费。

---

## 2. 总体工作包顺序

必须按以下顺序执行：

0. 工作包 0：知识资产分层与 registry 轻量前置。
1. 工作包 A：现状基线和目标样例锁定。

5. 工作包 E：`CodingAgent` 展开 subflow body。

7. 工作包 G：最小 workflow 闭环和负样本测试。
8. 工作包 H：文档和 trace 诊断补齐。

暂不进入：

- LLM requirement enrichment。
- LLM template rerank。
- LLM interface adapter。
- RepairAgent 扩面。
- Send 并行。

这些放到 body 编译闭环通过之后。

## 3. 工作包 0：知识资产分层与 registry 轻量前置

### 3.1 目标

明确知识库的事实源、可重建缓存和按需加载边界，避免后续把完整 raw flow 或完整模板 body 全量塞进检索上下文。

本工作包不做大规模知识补全，只建立最小可执行的组织口径。

### 3.2 事实源与缓存边界

- 原子模块事实源：`schemas/*.json`。
- AHU 真实样例事实源：`AHU程序/flows_*.json`。
- AHU 模板缓存：`AHU程序/pattern_library/*.json`。
- 运行时检索缓存：Chroma collections。

`schemas/*.json`、`flows_*.json` 是事实源；`pattern_library`、Chroma、后续 `knowledge_index` 都应可重建。

### 3.3 分层模型

采用类似 skills 的渐进式披露：

| 层级 | 内容 | 第一轮用途 |
| --- | --- | --- |
| L0 registry / manifest | asset id、类型、来源、hash、locator | trace、健康检查、按需加载 |
| L1 摘要卡片 | 名称、角色、关键词、端口摘要 | Retrieval / planner 轻量检索 |
| L2 结构化合同 | `parameters_schema`、`ports_definition`、`template_json` | compiler / verifier 使用 |
| L3 raw body / source slice | `internal_flow_objects`、source flow slice | body 编译和 golden diff |

### 3.4 建议新增或扩展

第一轮可以先最小实现，不必一次性建设完整 `knowledge_index`：

- `utils/knowledge_contract_loader.py`
  - 按 `module_type` 从 `schemas/*.json` 加载 L2 合同。
  - 按 `template_id` 从 `subflow_templates.json` 加载子流程 L2/L3。
- 可选扩展 `scripts/build_phase2_retrieval_indexes.py`
  - 在 manifest 中记录 asset id、source hash、asset level。

### 3.5 完成标准

### 5.3 最小校验规则

实现函数建议：

```python
def validate_flow_document(flow_objects: list[dict]) -> dict:
    ...
```

返回结构建议：

```json
{
  "status": "passed | failed",
  "issues": [],
  "warnings": [],
  "metrics": {
    "object_count": 0,
    "page_count": 0,
    "subflow_count": 0,
    "subflow_instance_count": 0,
    "body_node_count": 0
  }
}
```

必须检查：

- 顶层必须是 list。
- list 内每项必须是 dict。
- 每个对象必须有唯一非空 `id`。
- `tab` 对象必须有 `label`。
- `subflow` 对象必须有 `name/in/out`。
- `subflow:<id>` 必须引用真实 `subflow` id。
- 非 `tab/subflow` 对象如果有 `z`，`z` 必须存在。
- `wires` 必须是 list。
- 每个 wire target 必须是 dict，且 `id` 指向真实对象。
- wire target `port` 必须是非负整数。
- 高频普通节点如果存在对应 `schemas/*.json` 合同，按合同校验基础字段：
  - `template_json.type` 与节点 `type` 一致。
  - `parameters_schema` 中有枚举或范围的字段不能越界。
  - `ports_definition` 与 `inputs/outputs` 的基础数量不矛盾。
  - 残留 `{{placeholder}}` 必须失败。

第一轮合同消费优先覆盖：

- `swInput`
- `quote`
- `pid`
- `modbusOutput`

### 5.4 正样本

三个真实文件必须通过：

- `AHU程序/flows_20251210190941.json`
- `AHU程序/flows_20251229175702.json`

## 6. 工作包 C：strict compile 诊断字段

### 6.1 目标

让编译器不再只把高风险问题放在 warning 中，而是输出可被 verifier 升级为 error 的结构化诊断字段。

### 6.2 修改文件

- `utils/graph_ir.py`
- `agents/coding_agent.py`
- `agents/verifier_agent.py`
- 相关测试文件

### 6.3 修改点

扩展 `CompileReport`：

```python
class CompileReport(BaseModel):
    node_count: int = 0
    subflow_count: int = 0
    page_count: int = 0
    body_node_count: int = 0
    dropped_node_count: int = 0
    missing_template_count: int = 0
    unresolved_placeholder_count: int = 0
    body_expansion_errors: list[str] = Field(default_factory=list)
    warnings: list[str] = Field(default_factory=list)
```

`CodingAgent` 遇到以下情况时要增加结构化计数：

- 缺少 `page_id/subflow_id` 导致跳过节点：`dropped_node_count += 1`
- 缺少 `module_type` 模板定义：`missing_template_count += 1`，同时 `dropped_node_count += 1`
- 子流程定义缺失：`dropped_node_count += 1`
- 占位符残留：`unresolved_placeholder_count += 1`
- body 展开失败：写入 `body_expansion_errors`

`VerifierAgent` 中增加 hard fail：

- `dropped_node_count > 0`
- `missing_template_count > 0`
- `unresolved_placeholder_count > 0`
- `body_expansion_errors` 非空

### 6.4 注意事项

- 第一轮可以保留原 `warnings`，但不能只依赖 `warnings` 判定。
- 不要删除已有字段，避免 API / 前端投影回归。
- 新字段默认值必须向后兼容旧测试 fixture。

### 6.5 完成标准

- 旧 fixture 缺少新字段时不报错。
- 新编译产物包含新增 compile_report 字段。
- 编译器跳过节点时 verifier 必须失败。

## 8. 工作包 E：`CodingAgent` 展开 subflow body

### 8.1 目标

编译子流程定义时，同步输出其内部 body 节点，并完成稳定 ID 重映射。

### 8.2 修改文件

- `agents/coding_agent.py`
- `tests/test_coding_subflow_body_expansion.py`

### 8.3 推荐实现拆分

在 `CodingAgent` 中新增私有方法：

```python
def _compile_subflow_body_objects(
    self,
    subflow_definition: dict,
    definition_real_id: str,
    used_ids: set[str],
) -> tuple[list[dict], dict[str, str], list[str]]:
    ...
```

职责：

- 输入 `internal_flow_objects`。
- 为每个 body 对象生成稳定新 id。
- 建立 `body_id_map: raw_id -> real_id`。
- 将每个 body 对象的 `z` 改成 `definition_real_id`。
- 重写 body 对象内部 `wires[*][*].id`。
- 返回 body 对象、映射表和错误列表。

还需要调整 `_compile_subflow_definition()`：

- 子流程定义对象的 `id` 改成 `definition_real_id`。
- `in/out.wires` 中的目标 id 也要按 `body_id_map` 重写。
- 如果 `in/out.wires` 指向不存在 body 节点，记录 body expansion error。

### 8.4 稳定 ID 规则

seed 建议：

```text
subflow_body::<definition_id>::<raw_body_id>
```

要求：

- 同一输入多次编译 id 稳定。
- 不与 page、subflow、node instance id 冲突。
- `id_map` 可考虑记录 body 映射，格式可为：
  - `body::<definition_id>::<raw_id> -> real_id`

### 8.5 计数规则

`compile_report` 更新：

- `body_node_count` = 展开的 body 节点数量。
- `node_count` 应包含 subflow instance、普通页面节点、body 节点。
- `subflow_count` 只统计 `type=subflow` 定义对象。
- `page_count` 只统计 `type=tab`。

### 8.6 测试要求

新增测试：

- `test_compile_subflow_definition_expands_internal_body`
- `test_subflow_body_ids_are_remapped`
- `test_subflow_body_z_points_to_real_subflow_id`
- `test_subflow_definition_in_out_wires_are_remapped`
- `test_subflow_body_wire_targets_are_valid`
- `test_subflow_body_compilation_is_stable`

### 8.7 完成标准

- 最小模板编译后，`flow_objects` 中同时存在：
  - `tab`
  - `subflow`
  - body nodes
  - `subflow:<id>` instance
- 所有 body 节点 `z` 都等于真实 subflow id。
- 所有 body wires target 都存在。
- `compile_report.body_node_count > 0`。
- 重复运行输出 canonical JSON 一致。
